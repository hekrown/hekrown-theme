# Moss Theme — Project Proposal

**Prepared for:** Management
**Prepared by:** Development Team
**Date:** June 4, 2026
**Re:** Turning the Moss theme into a sellable commercial product

---

## Executive Summary

We originally built Moss as a custom Shopify theme for a single fashion store. The work has gone well — the theme is roughly **85% complete as a website**, passes Shopify's quality checks, and already includes premium features that most stores pay monthly app subscriptions to get.

We're proposing a strategic shift: **rebuild Moss into a commercial theme product** that any merchant can buy, install, and fully customize without writing code. This positions us to sell the theme repeatedly rather than use it once.

The headline opportunity: **build in features that merchants normally rent from apps** (worth an estimated **$120–250/month** per store), and offer them for a single one-time price. That's our competitive edge.

## The Opportunity

### Problem with the current approach
Right now the theme is configured for one store. It looks great, but a different merchant couldn't use it without a developer changing the code. That limits it to a one-time, single-client asset.

### The shift
Turn every design decision into a **setting**, and every layout into **drag-and-drop building blocks** the merchant controls themselves. This is exactly how Shopify's own flagship theme (Horizon) and premium paid themes work.

### Why it's worth it
1. **Sell it many times** instead of once.
2. **App-replacement is a powerful sales hook.** Merchants typically stack multiple paid apps (wishlist, reviews, FAQ, countdowns, upsells) costing $120–250/month combined. We build those in.
3. **We already have a head start** — several of these features are done.

---

## What We'll Build

### 1. A flexible building-block system
The foundation. Instead of fixed layouts, merchants will assemble pages from reusable content blocks (text, images, buttons, product info, etc.) they can add, remove, and reorder — no code. This is the modern industry standard and unlocks everything else.

### 2. A much larger library of page sections
Expanding from 24 to **40+ sections**, including the ones merchants expect: testimonials, FAQ, featured products, countdown timers, video banners, newsletter signups, logo lists, image galleries, and more.

### 3. Deep customization controls
- Multiple **color schemes** merchants switch between instantly
- Typography, spacing, button, and layout controls
- Per-section styling options
- **Ready-made starter designs** so a fresh install looks complete immediately

## Plan & Phases

The work breaks into clear phases. Each delivers something usable.

| Phase | Focus | Outcome |
|---|---|---|
| **6** | Building-block foundation | The customization engine everything else relies on |
| **7** | Color schemes & global controls | Merchants restyle the whole theme in minutes |
| **8** | Core section expansion | The most-requested sections merchants expect |
| **9** | Customizable product page | Merchants rearrange the product page freely |
| **10** | App-replacement features | Reviews, upsells, popups, shoppable images, etc. |
| **11** | Third-party app support | Compatibility with popular apps merchants already use |
| **12** | Starter designs & demo content | Theme looks complete out of the box |
| **13** | Performance & launch prep | Speed, polish, documentation, store submission |

We recommend starting with **Phase 6** because the building-block system unblocks and improves every later phase.

---

## Decisions We Need From You

1. **Sales channel** — Do we sell through the official Shopify Theme Store, a marketplace (e.g. ThemeForest), or private licensing? *This matters because the Shopify Theme Store has strict rules that could limit a few of the built-in app features.*

2. **Timeline & resourcing** — How many developers and what target launch window? This is a multi-phase effort.

3. **Pricing model** — One-time price point, and whether we offer support/updates.

4. **Scope priority** — Full plan, or a faster first release with the highest-impact features (blocks, color schemes, top sections, existing app features) and the rest in a v2?

---

## Recommendation

Proceed with the shift to a commercial product, starting with the building-block foundation (Phase 6). It's the highest-leverage work: it directly enables the customization depth that distinguishes a sellable theme from a one-off website, and it makes every subsequent phase faster to build.

We suggest an early decision on the **sales channel**, since it shapes which app-replacement features we can include.
